# 11 晨的地形重塑

2026-10-25。第一版试玩后，用户指出晨的全球地形"有很多突兀的地形，像是硬凑出来的"。本规格把晨的大尺度地形从"运行时叠加公式"改成"离线雕刻、侵蚀、烘焙成高度场"。对应 [分步交接](20-分步交接.md) 的第 2 步。

这是改动最大的一步：地形一变，古城、塔链、天梯、洞穴、攀爬路线、回声锚点都要重新选址或重新烘焙。所以它排在主线模型重做（第 3 步）和引导（第 4 步）之前。

## 一、为什么现在的地形显得硬凑

晨的地形现在是这样算的：`TerrainNoise.base_height()` 叠几层噪声，再由 `TerrainFeatures.apply()` 依次叠加主山脉、大峡谷、火山、河道、文明区、洞穴。每一层都是一个独立的数学公式，边界靠 `smoothstep` 混合。

问题出在"每一层都是公式"：

| 突兀的地方 | 原因（代码） |
| --- | --- |
| 高地上一圈圈等高的台阶、台地叠台地 | `base_height()` 里的 `terraced = floorf(tier) ...`，按 180 米等高线切台阶 |
| 海边突然立起一道崖 | `coastal_bluff`，按噪声阈值直接抬高 65 米 |
| 盆地是一个平底的碗 | `basin`，阈值内整体下压 70 米 |
| 火山是一个规整的圆锥，冲沟是放射状的余弦条纹 | `with_volcano()` 按距离算锥体，冲沟用三角函数 |
| 主山脉像一条均匀的带子，两侧坡度处处一样 | 脊线是十段折线，断面是同一个剖面沿脊线扫过去 |
| 峡谷像用模具压出来的，岩壁是完全平行的等高台阶 | 峡谷路线是十二段直线，台阶按固定高度切 |
| 沟谷是细长的等值线，不像水冲出来的 | `drainage` 取噪声绝对值的等值线下切，和真实水流方向无关 |
| 各个特征之间没有过渡 | 每个特征都是在别人的结果上直接加减，没有一个过程把它们"磨"在一起 |

真实的地形是**先抬升、再被水和重力侵蚀**形成的。山坡上的沟、山脚的冲积扇、坡底的碎石堆、河谷的形状，都是侵蚀的结果，各个地貌之间也是被侵蚀连起来的。公式叠加做不出这些，所以看起来"硬"。

## 二、新的做法

> 意图图 → 高度场生成 → 侵蚀 → 烘焙成立方体高度场 → 运行时采样，再叠加小尺度细节和后续特征

### 1. 意图图（保留现在的地理）

晨的大格局已经和故事绑在一起：出发地在海边、主山脉横在天边、峡谷在侧方、火山在出发地附近。这些**位置不变**，变的是形状。

- 新写一个 Godot 导出脚本 `game/scripts/tools/terrain_intent_export.gd`，从现有数据导出"意图"：
  - 每个立方体面 512 × 512 的**低频地势**：现在的 `base_height()` 去掉 `terraced`、`plateau`、`coastal_bluff`、`basin`、`drainage` 和 `detail` 之后的结果，也就是"大陆、海洋、高地、山脚"的大轮廓；
  - 遮罩：主山脉的抬升带（按脊线距离和名峰位置）、峡谷路线、火山位置和尺寸、出发地两公里保护区；
  - `dawn_layout.tres` 里的脊线、名峰、山口、峡谷路线、火山、出发地，原样写成 JSON。
- 导出结果放在 `test-output/terrain/intent/`，不进仓库；它可以随时从现有代码重新生成。

### 2. 高度场生成与侵蚀（离线工具）

新写 `tools/Bake-Terrain.py`，读意图，输出最终高度场。用 Python 加 NumPy 和 Numba（只在烘焙时需要，和 Blender 一样不进游戏运行环境；依赖写进 `tools/requirements-bake.txt`）。

选 Python 而不是 GDScript：侵蚀要模拟几百万滴水，每滴走几十步，GDScript 要算几个小时；Numba 编译后几分钟。选 Python 而不是 GPU 计算着色器：单线程 CPU 实现可以做到每次结果完全一样，出了问题也容易调试。

处理顺序：

1. **底**：意图里的低频地势上采样到每面 2048 × 2048（格距约 31 米）。立方体面之间按共享边处理，面与面的接缝两侧必须连续。
2. **抬升**：在主山脉抬升带内叠加**域扭曲的脊状分形噪声**，并用**导数衰减**（坡度越大，后面的高频层振幅越小），这样山脊尖、山坡上长出自然的分支脊，而不是处处一样的凹凸。名峰按布局抬高到指定高度，形状各不相同（第二节第 6 条）。主山脉之外的高地用同样的方法，振幅小得多。
3. **火山**：保留位置、高度和火山口，但锥体用"径向剖面 + 噪声扰动的半径"生成，不再是正圆锥；冲沟交给侵蚀产生。
4. **峡谷主体**：沿布局路线挖出峡谷的大断面（宽度和深度沿途变化，路线用平滑曲线而不是十二段直线），深度 700～1000 米。台阶状岩层**不在这里做**，见第五节。
5. **水力侵蚀**：水滴模拟（每滴带沙，按坡度加速、冲刷、沉积、蒸发），固定种子，水滴总数和每滴步数按格网规模定（起点：每面 50 万滴、每滴最多 80 步），写进记录。要的效果：山坡上有分支的冲沟，沟口有冲积扇，河谷是水冲出的形状。
6. **热力侵蚀**：坡度超过休止角（约 35°）的地方让物质往下滑，山脚形成碎石坡，悬崖顶变圆。峡谷岩壁和名峰的刀脊要保留陡峭，在这两处用"岩性硬度"遮罩降低侵蚀量。
7. **出发地保护**：出发地两公里内用意图里的原始地势，向外三公里平滑过渡到侵蚀后的结果，保证 `spawn_clear` 和出发地的样子不变。
8. **海岸**：海平面附近按侵蚀结果自然形成海滩和小崖，不再用阈值抬崖。海平面不变。

### 3. 输出

- `game/data/dawn_terrain.res`：六个面，每面 (2048 + 4)²（每边留两格边框，供双三次插值跨面采样），16 位整数编码高度（范围 -500～4300 米，精度约 0.07 米），用资源压缩保存。文件头记录格网大小、高度范围、生成参数和意图的哈希。
- 预计压缩后 25～35 MB；加入出发地八米采样后实际约 43.8 MiB，可以接受，但不得超过 46 MB（见第九节）。迭代调试时的中间结果放 `test-output/terrain/`，**只在这一步完成时提交一次**，避免仓库里堆很多版大文件。

### 4. 运行时采样

- 新类 `DawnHeightfield`（`game/scripts/planet/dawn_heightfield.gd`），加载 `dawn_terrain.res`，提供 `sample(direction) -> float`：方向转面和面内坐标，双三次插值。
- 晨（`profile == 0`）的 `base_height()` 改为：高度场采样 + 小尺度细节噪声（只补格距以下的起伏；振幅上限按第九节第 2 条调整为 6 米）。烬和霜（`profile 1、2`）不变。
- 主山脉、火山原来在 `TerrainFeatures.apply()` 里的运行时叠加删除，因为已经烘焙进高度场。`DawnLandforms` 只保留峡谷的岩层台阶、冰川和地表标记。
- 性能：`height()` 的单次耗时不能比改动前慢。改动前先测一次现在的耗时，写进记录作为基线。

### 5. 后续特征的顺序

[工程约定](02-工程约定.md) 第二节第 0 条的叠加顺序改为：

> **烘焙高度场**（意图 + 抬升 + 火山 + 峡谷主体 + 侵蚀）→ 峡谷岩层台阶 → 河道 → 文明区（平整、道路、梯田、天梯基座）→ 洞穴（天坑、开洞）

"高度函数是唯一来源""确定性""出发地不动"这几条规则不变：高度场是烘焙好的只读数据，任何线程、任何时候查询结果都一样。

### 6. 地貌参数

第一版的主山脉、名峰、山口、峡谷参数沿用，位置以 `dawn_layout.tres` 为准，只是改由烘焙生成：

| 地貌 | 参数 |
| --- | --- |
| 主山脉 | 脊线 60～80 公里，离出发地最近处 6～10 公里，从出发地看横在前方；离海岸至少 4 公里；半宽 7～10 公里 |
| 角峰 | 金字塔形尖峰，三四面陡壁，高 3.8～4.0 公里 |
| 双子峰 | 两座尖峰相距约 900 米，中间一道深 V 形缺口 |
| 平顶峰 | 四壁陡峭、顶部约 600 米范围平坦的桌状山 |
| 山口 | 2～3 处，彼此相距 15 公里以上；鞍部宽约 1.5 公里，两侧坡度不超过 0.35，能走过去；古道、塔链、以后的青晶洞都利用山口 |
| 冰川 | 海拔 2200 米以上、坡度小于 0.3 的谷底 |
| 大峡谷 | 离出发地 10～25 公里，和主山脉方位相差 60° 以上；长 20～30 公里，深 700～1000 米，顶宽 1.5～3 公里，谷底宽 150～300 米；一端通海或大湖，谷底单调下降；两侧岩壁不对称 |

## 三、重新烘焙和重新选址

高度场换掉以后，下面这些全部按现有流程重跑：

| 内容 | 怎么做 | 注意 |
| --- | --- | --- |
| 全球水系 | `Bake-World.ps1` 的水系阶段改为读新高度场 | 侵蚀已经把谷底挖出来，河流应该更自然地落在谷里；对比新旧河流总长和湖泊数 |
| 古城、天梯、塔链、道路、桥、水渠、梯田、墓园 | 文明阶段原样重跑 | 选址失败时，**不降低选址阈值**；改为在意图图上把目标区域的河岸稍微放平，重新烘焙。第一版的画面打磨就遇到过这种情况 |
| 洞穴 | 洞穴阶段原样重跑 | 回声洞入口要落在新的山坡上；回声洞第二出口这次接到规定的河谷（第一版没有做到） |
| 攀爬路线、栈道 | `climb_bake.gd` 重跑 | 十条路线的检查都要通过 |
| 回声锚点、手记地点、降落点 | 随文明和洞穴阶段重新生成 | `echo_checks`、`civilization_checks` 通过 |
| 地图、地球仪、小地图 | 自动从高度函数生成 | 看一遍大地图，确认分层设色和等高线正常 |

主线的节奏要保持：出发地到古城、古城到回声洞、回声洞到第一座烽火塔的距离，和第一版相比变化不超过 30%。古道普通步行约 45 分钟这个问题，这一步顺便处理：古城选址时把"离出发地的步行距离"加进评分，目标是普通步行 15～20 分钟能到。

## 四、不做的事

- 不用 Gaea、World Machine 这类图形化地形软件。它们效果好，但结果不能由脚本重复生成，也没法交给编码会话执行。
- 不改烬和霜。
- 不移动出发地、不改海平面、不改星球半径。
- 不在这一步加新地貌（石林、温泉、第二座火山在第 8 步，见 [15 地貌补充](15-地貌补充.md)）。

## 五、峡谷岩层（同时解决第一版的"千层蛋糕"）

峡谷主体在高度场里，岩层台阶仍然在运行时按 `DawnLandforms` 叠加，因为 45 米宽的陡壁比 31 米格距还细。改动：

- 台阶数量 8～11 级，每级高度不等（40～120 米），台阶边缘按噪声前后错动 5～20 米，不是完美的等高线；
- 少数几级台阶在局部坍塌，形成碎石坡（坍塌处跟热力侵蚀的结果一致，由烘焙时写一张坍塌遮罩）；
- 颜色：基色向圣经的石材色靠拢（浅赭 `#D6C7A4`、暖灰 `#B8A58A`、淡红褐 `#B07A5A`），饱和度比第一版低一半，不要粉色和紫色；色带宽度 5～40 米不等、相邻色差小、只有少数深色带、叠加竖向流痕；**看不到等距的白色细线**；
- 平台朝上的面是土色加稀疏草色。

## 六、自查与验收

### 自动检查

扩展 `landform_checks`，新增：

1. 立方体面接缝：沿 12 条棱抽样，接缝两侧高度差不超过 0.5 米，法线夹角不超过 3°；
2. 坡度分布：峡谷和名峰之外，坡度超过 45° 的面积比例低于 2%；
3. 汇水：陆地格子沿最陡方向往下走，都能到达海或湖（除湖泊外没有封闭洼地）；出发地保护区内保留的旧地形出水边是允许的例外，单独统计数量，不计为失败（第九节第 7 条）；
4. 没有台阶：在主山脉、高地、盆地抽样，高度的直方图上没有 180 米间隔的尖峰；
5. 名峰高度、山口高度、峡谷深度、火山口深度在第二节第 6 条的范围内；
6. 出发地：`spawn_clear` 通过，出发地两公里内的高度和改动前相差不超过 1 米；
7. `height()` 单次耗时不超过改动前的基线。

`hydrology_checks`、`ecology_checks`、`ecology_runtime_checks`、`surface_checks`、`civilization_checks`、`cave_checks`、`traversal_checks`、`echo_checks` 全部通过。这一步结束时跑 `Test-Acceptance.ps1 -Scope dawn`。

### 人工确认（由 GPT 自查，Claude 审图）

- 从出发地四个方向看，有没有任何一处地形"一看就是公式"：直线、正圆、等距、平顶、突然的崖。有就修。
- 从 3 公里高空看，山、谷、河、海岸是不是一个连贯的整体。
- 古城、回声洞、塔链、天梯的新位置是否仍然合理：古城在河边平地、塔在山顶两两相望、天梯从出发地和古城都看得见。
- 主线步行时间是否落在第三节的范围内。

## 九、第 2 步修正（2026-10-26 审图后补充）

第一轮实现的审图结论见 [第 2 步记录](记录/第2步-地形重塑.md) 末尾。公式痕迹消除、保护区、山口、选址、水系连通、古道约 19 分钟、洞口往返、回声逐点碰撞都已通过，**不要改坏**。问题是侵蚀几乎看不出来，山体变得光滑平淡。下面各条必须修，修完重新审图。

### 1. 侵蚀强度不够

- 现象：`s71`、`s74`、`s76` 的山体是光滑的大坡，没有分支冲沟、冲积扇、刀脊。
- 原因：每面 2048²（约 420 万格）只滴了 50 万滴，平均每格 0.12 滴；公开实现一般每格 1～3 滴。
- 要求：
  - 改成多分辨率侵蚀：先在每面 1024² 上侵蚀，每格平均不少于 2 滴（每面约 210 万滴以上）；上采样到 2048² 后再做一遍收尾侵蚀，每格不少于 0.5 滴；每滴最多步数可以提高到 120；
  - 冲沟要在 2～6 公里外看得出来：主山脉山坡上的主冲沟间距约 150～400 米，向下汇合成树枝状；
  - 烘焙总耗时上限 30 分钟（本机），参数和耗时写进记录；
  - 结果仍要可重复：同样输入两次生成哈希一致。

### 2. 缺少 50～300 米这一档起伏

- 原因：烘焙噪声最细只到约 160 米波长，规格又把运行时细节限制在 3 米以内（这是规格本身的缺口）。
- 要求：
  - 烘焙时在侵蚀**之前**补中频脊状细节，最短波长约 60 米。振幅按抬升和坡度分配：主山脉 40～120 米，丘陵 10～30 米，平原和海岸接近 0；让侵蚀在这层起伏上切出沟谷；
  - 运行时细节噪声的振幅上限从 3 米放宽到 6 米，波长 20～60 米，只在坡度大于 0.3 的岩坡和高地使用；出发地保护区、文明区平整范围、道路、洞口不加；
  - 刀脊：名峰和主脊线附近保留锋利的山脊，热力侵蚀在这些地方用硬度遮罩减弱（第二节第 2 条第 6 点已有，加强）。

### 3. 火山没有变化

- 现象：`s75` 改动前后几乎相同，仍是光滑正圆锥。
- 要求：侵蚀前给锥体加噪声扰动的放射状浅沟（6～12 条，宽窄、长短不一），让侵蚀在上面加深；火山口沿口不等高、有一处缺口。判断标准：`s75` 里能数出至少 6 条冲沟，侧面轮廓不是两条直线。

### 4. 山坡上的直沟

- 现象：`s76` 山坡上一道又窄又深、近乎笔直的暗沟。
- 要求：查明来源（大概率是水系河道在高度场上刻得太窄太深），写进记录。峡谷之外，河道横断面宽度至少 3 个格距，两岸平滑过渡到坡面，深宽比不超过 0.3；山坡上的河道沿侵蚀形成的谷底走，不是直线。

### 5. 峡谷

- 现象：`s77` 远壁仍是整面细而平行的横线；近处原有的台阶和谷底河流被一个模糊的大土坡盖住。
- 要求：
  - 侵蚀和热力侵蚀不得填平峡谷：峡谷内部禁止沉积，谷底宽度和河流保留；近处的台阶清楚可见；
  - 岩层颜色：从 `s77` 的距离看，整面岩壁只能分辨出 6～10 条色带，宽窄不一，相邻色差小；细线合并或删掉；色带边缘随噪声起伏，叠加竖向流痕；
  - 判断标准：`s51`、`s52`、`s54`、`s77` 都看不出"千层蛋糕"，谷底能看到河。
