# 12 主线近景

2026-10-26。对应 [版本计划](版本计划.md) 第二版的第 3 步。目标：主线上走路不会被卡住；近看的东西不再是"程序拼出来的"；描边只勾立起来的东西。第一节的建模标准对之后所有模型都有效。

## 一、建模标准

原则来自用户：**人和东西要用真正的建模工具做，不能是代码拼凑**；地形、洞穴、天梯主体这类超大尺度的东西继续程序生成。

### 工具与流程

- 建模脚本在 `art/blender/`，由 `tools/Build-Models.ps1` 调用（Blender 4.x，脚本开头检查版本）。一条命令能重建全部模型；布料和刚体模拟用固定帧数和种子。
- 脚本调用的是 Blender 的建模工具：修改器、布料和刚体模拟、曲线、几何节点、雕刻位移、骨骼。脚本里直接列顶点坐标、拼面，只允许用于碰撞体和极简单的块。
- **不允许**在 GDScript 里为新物件手写网格。`RuinKit` 读取的 `geometry.json` 备用数据由导出脚本自动生成，可以保留。
- 通用自然物（石头、植物、叶片）优先用 CC0 素材：Quaternius、Kenney、KayKit、Poly Haven。原始文件放 `art/sources/<来源名>/`，来源、作者、链接、授权写进 `art/sources/来源.md`。素材只取形状，丢掉原有贴图和材质，改成我们的比例、倒角、顶点色和着色器后才能进场景。

### 去掉塑料感的硬性要求

1. **倒角**：所有边都要倒角，宽度约为物体短边的 2～5%，至少 2 段。
2. **轮廓不规则**：石材、墙、柱子的边缘有轻微的不平和缺口；超过 2 × 2 米的平面要有起伏、分块或破损。
3. **法线**：用加权法线（Weighted Normal 修改器），大平面保持平，倒角处圆滑过渡。
4. **烘焙到顶点色**：环境光遮蔽，以及由曲率得到的边缘磨损（凸边略亮、凹缝略暗）。
5. **修边贴图**：一套共用的石材修边贴图（砌缝、横带、刻纹、破损边各一条），墙、台基、塔身、门框都从这张图取 UV。
6. **封闭和朝向**：封闭物体没有开口，所有面的法线朝外；开放的单面（叶片、布条）按"离开附着面的方向"检查。

### 常用做法

| 要做的 | Blender 里的做法 |
| --- | --- |
| 人形基础 | 顶点串加蒙皮修改器（Skin）再细分；或骨架加简单网格 |
| 姿势 | 骨架摆出站、跪、坐等姿势 |
| 长袍、兜帽、袖子 | 布料模拟罩在摆好姿势的人体上，肩颈固定，模拟若干帧后应用；布料分辨率低一些，褶子大而简洁 |
| 藤条、绳子、缆索 | 曲线加倒角，半径沿曲线渐细 |
| 叶子沿藤条分布 | 几何节点：曲线上取点，实例化叶片，随机旋转缩放 |
| 石头 | CC0 石头；或二十面球 → 体素重建 → 噪声位移 → 减面 → 倒角 |
| 一堆碎石 | 刚体模拟把石块丢下，静止后应用 |
| 断面 | 布尔差集，切割体先做噪声位移 |
| 墙、柱、台阶 | 倒角、阵列、实体化等修改器，加修边贴图 |
| 减到面数预算 | 减面修改器，最后一步做 |

### 规范

| 项目 | 规则 |
| --- | --- |
| 单位 | 1 = 1 米 |
| 坐标 | Blender 里按 +Z 建模，导出打开 `export_yup=True`；Godot 里 +Y 向上，正面朝 -Z |
| 原点 | 底面中心；墙段在底边中点 |
| 模数 | 水平以 1 米为模数，墙厚 0.6 米，层高 3.6 米 |
| 变换 | 导出前应用所有变换，缩放为 1 |
| 材质 | 最多四种，按名字区分：`stone`（石材）、`patina`（铜锈）、`glyph`（琥珀光纹，略微凹进的面片）、`cloth`（布）。导入时由代码换成项目着色器 |
| UV | 石材按 1 米一格立方体投影；用修边贴图的部分按贴图条带展开 |
| 顶点色 | R：环境光遮蔽（0.6～1）；G：布料摆动权重（固定端 0，自由端 1）；B：边缘磨损（0.5 为中性，凸边更高，凹缝更低） |
| 碰撞 | 物体名以 `-colonly`（凹体）或 `-convcolonly`（凸体）结尾，面数 ≤ 64；台阶和坡道的碰撞做成斜面；高于 0.5 米的物件必须有碰撞 |
| 细节层级 | 导入开启自动 LOD；LOD0 面数上限：小件 300、中件 1800、大件 4000、雕像 5000、回声人影 3000、碎石 900、藤蔓 2000～3000 |

### 自查

每个模型用 EEVEE 渲一张四视图（正、侧、背、三分之二侧，中性灰底，一盏方向光），另出一张灰度图和一张剪影图，输出到 `test-output/models/<名字>.png`。先看图确认轮廓、比例、面的朝向，再进 Godot。

## 二、重要地点整体建模

### 为什么换做法

古城广场、神殿、天梯基座现在是 GDScript 在烘焙时用公式一块块摆出来的：一个循环铺石板，一个公式放墙。摆石板的循环不知道旁边有路，放水渠的公式不知道自己悬在半空，所以出现了石板交叠、人物被卡住、像棋盘、水渠悬空。行业的做法是**重要地点整体做、其余程序生成**。

### 做法

五个重要地点改成在 Blender 里用脚本建成**一个完整的场景**：

| 地点 | 范围 |
| --- | --- |
| 古城广场 | 广场、纪念环、周围第一圈房屋、广场边的矮墙和台阶、道路进入广场的接口、经过广场附近的一段水渠 |
| 神殿大厅 | 大厅地面、壁柱、壁画板、巨像和台座、天井口、通往前厅和侧廊的门洞 |
| 天梯基座 | 三层台地、台阶、扶壁、主门、巨像高台、灯柱和残旗 |
| 烽火塔顶 | 塔冠平台、火盆、塔冠入口 |
| 断口平台 | 环形平台、停泊台、栈桥、终章圆台 |

1. **设计稿**：每个地点先写一份布局数据 `art/blender/sites/<地点>.json`：由哪些部分组成、各自的位置、尺寸、朝向、彼此怎么衔接（例如"道路在广场东侧以 4 米宽的口接入"）。
2. **建模**：Blender 脚本按设计稿建出整个场景。**走的面和看的面分开**：
   - 一张平顺的**行走面**网格，覆盖所有能走的地方，作为唯一的地面碰撞；台阶做成斜面碰撞；
   - 石板、路石、台阶踏步、墙、柱等只负责外观，按第一节的标准做，贴合行走面，互相对齐、不交叠；
   - 墙、柱、雕像这类立起来的东西用自己的简化碰撞。
3. **导出**：每个地点一个 glb（外观）加一个碰撞场景，另写一份元数据：占地轮廓、底面高度、道路接口位置。
4. **放进游戏**：烘焙只决定地点的位置和朝向；地形按元数据里的占地轮廓整平（写进高度函数，规则不变）；道路寻路连到元数据里的接口，不再伸进广场。
5. 原来在 `CivilizationBuildings` 等处用公式摆放这几个地点的代码删除，不保留两套。

### 顺序

**先只做古城广场**，作为样板：建模、碰撞、描边、卡住检测、画面检查全部达标后，再按同样的流程做其他四个。广场做不好就不往下推。

## 三、人物被卡住

用户试玩发现：在古城广场和道路上走，人物会被卡住走不动；路石和广场石板互相交叠、互相卡住。注意这里的"卡"是**走路被挡住**，不是帧数低。

读代码看到的原因：

1. 每块石板一个独立的碰撞盒（`floor_slab` 是 2×2×0.4 米的盒子，`road_stone` 也是盒子），相邻两块顶面差几厘米就形成小台阶；
2. 石板按球面径向朝上摆放，只在中心点取地面高度；地面有坡度时一边埋进地里、另一边翘起，10% 的坡上 2 米宽的石板会翘起约 0.2 米；
3. 玩家是半径 0.3 米的胶囊体，`CharacterBody3D` 本身不会迈台阶；
4. 道路的路石一直铺进广场，和石板重叠。

要求：

- 五个重要地点按第二节"走的面和看的面分开"重做，这一条在那里解决；
- 重要地点之外的道路、桥、台阶，同样改成按段合并的平顺碰撞，单块路石不再各自带碰撞；路石按地面法线摆放，相邻顶面高差不超过 3 厘米；
- 角色加上台阶处理：前方障碍高度不超过 0.25 米、上方有空间时自动迈上去；高于 0.25 米的仍然挡住。如果默认物理引擎仍有贴边卡住的问题，评估切换到 Godot 内置的 Jolt 物理引擎，切换后要跑全部移动、飞船、攀爬、滑翔、升降台检查；
- 散落的小碎石、矮石块：要么不带碰撞，要么用圆滑的凸包；
- 完成标准：[10](10-自动检查.md) 的卡住检测在所有可走区域为 0 次，摆放检查没有交叠。

## 四、描边太多

- 现象：古城广场的每一块石板都被描了一圈，整片广场变成网格线；道路铺石、低矮台阶同样如此；中景地形的坡顶有一条很粗的深色线（`s49`、`s71`）。
- 要求：
  - 只描"物体对背景"的轮廓：深度跳变要同时超过约 0.3 米和约距离的 1% 才画线；
  - 贴地的低矮物件（铺地、路石、梯田边、单级踏步、地面贴花，高度低于约 0.5 米）标记为不描边，可以用渲染层、实例参数或模板缓冲，选可靠的一种；接缝交给材质和顶点色；
  - 折角线只在 20 米内出现，强度减半；
  - 地形和地形之间的轮廓线宽减半。
- 完成标准：`s30` 广场上看不到网格状的描边，只有纪念环、树、墙、倒柱这些立起来的东西有轮廓；[10](10-自动检查.md) 的描边密度指标达标；`s62`、`s71` 的物体轮廓效果不能丢。

## 五、河流入海口和空心的石头

- **入海口**：主线附近（出发地 5 公里内和古城附近）每一个入海口截近景和俯视两张图，配合 [10](10-自动检查.md) 的水面检查逐个查：河面平顺地落到海平面，没有台阶、断口、悬空或两层水面；河岸到海滩平滑过渡，没有竖直的土墙；能走过去或绕过去，不卡人。修法写进烘焙和水面生成的规则，不手工改某一个河口。
- **空心的石头**：用户看到石头像空心的。查两种情况：网格缺面或法线朝里被背面剔除（地表石块用的是 `surface_solid.gdshader` 的 `cull_back`）；看得见却没有碰撞。所有石头网格（地表 `stone`、遗迹碎石 `rubble` 系列、峡谷石柱和石拱）都要通过 [10](10-自动检查.md) 的模型检查和摆放检查。

## 六、要重做的物件

不在第二节五个地点里的物件，按第一节的标准逐个重做：

| 物件 | 现在的问题 | 要改成 | 主机位 |
| --- | --- | --- | --- |
| 古城外围挡墙、梯田 | 挡墙有尖长变形的构件、排列过于规律；梯田轮廓弱；`s31` 山坡上几条平行的笔直细线 | 挡墙按修边贴图重做，高度和长度有变化、局部坍塌；梯田每级的挡土边清楚，沿等高线弯曲。先查明那几条直线是什么构件 | `s31`、`s32`、`s36` |
| 古城水渠 | 渠顶是一段段错开的台阶状折线，悬在天上；拱很细，远看像一排栅栏 | 渠顶沿等高线连续缓降；拱和墩有厚度和砌缝；断裂处断面自然，不悬空 | `s30`、`s31` |
| 古城道路铺石 | 白色小方块整齐排列，像卫生间瓷砖 | 大小不一、带倒角、颜色接近石材的路石，边缘残缺、混入土和草，不出现规则网格 | `s34` |
| 古城房屋 | 远看是小方盒 | 按第一节标准重做，穹顶或平顶加檐，局部坍塌 | `s31` |
| 观景环栏杆 | 一整块绿色实心平板挡住下半个画面 | 高约 1.0 米的矮石栏，中间是镂空的环与径栏板，每隔一段有缺口；平视能越过栏杆看到下方的大地和古城 | `s44` |
| 天梯断口外壳和缆索 | 外壳有规则的尖角，缆索偏细 | 断口按布尔加噪声做自然断面，缆索加粗并有下垂 | `s60` |
| 回声洞入口 | 入口边缘粗，门宽与空腔不协调 | 洞口构件和地形开洞重新对齐，边缘用岩石构件遮住 | `s37` |
| 回声人影 | 坐姿、跪姿衣摆有明显折面；单膝和盘坐轮廓不清 | 按第一节布料做法重做这几个姿势 | `s46`、`s47` |
| 烽火塔下的白色条带 | `s35` 远处绿坡上几段白色的台阶状条带 | 查明是什么，按对应规则重做，不出现孤立的白色色块 | `s35` |

**回声表演**也在这一步补齐：信仰回声的画师不被雕像遮挡，画圆、画线的动作和壁画亮起逐笔对应；终章老人真正举灯、放灯；日常回声里放下行囊、其他人跟随抬头。

五个重要地点里的具体要求（第二节建模时满足）：

- **古城广场**：6～8 种大小不一（0.6～1.6 米）、带倒角和缺角的石板，沿同心弧线和放射线错缝铺，越往外越稀，草从缝里长出成条成团；少数石板倾斜、翘起、缺失（只在外观上）；纪念环有台座；一侧矮墙和台阶通往房屋。
- **神殿大厅**：巨像是长袍人形，布料垂坠，双手捧环；地砖大小不一，靠墙有积土和碎石；天井光束是一道有体积的光柱，地面有清楚的光斑。
- **天梯基座**：扶壁是三到四级退台，每级顶面有压顶石，侧面有砌缝和横带；主门底部的黄色漏光查明原因修掉，门框退进层次加深。
- **烽火塔顶**：火焰是有体积的卡通火舌（几层向上收尖、彼此错开），从橙红到琥珀到浅黄渐变，有清楚的深色轮廓，不出现矩形；火盆是青铜绿带亮边、暗面暖褐，盆沿磨损处露出亮铜色；远景版本的三足完整。
- **断口平台**：按第一节标准重做外观，行走面平顺。

## 七、主线场景巡检

这一步最后，用 [10](10-自动检查.md) 的全部检查跑一遍主线，并看第 8 项的巡检截图：

- 卡住检测 0 次，摆放检查和模型检查没有失败；
- 每个场景的连续行走帧时间满足预算；
- 按工程约定第四节的低级问题清单逐张看截图，发现的问题列成表（位置、截图、属于模型、碰撞、描边、材质还是性能），这一步能修的直接修，修不了的写进 [03](03-现状与遗留.md)。

## 八、完成标准

- [10](10-自动检查.md) 的卡住、摆放、模型、水面、画面指标、连续行走全部通过；
- `ruin_kit_checks`、`packaged_asset_checks`、`echo_checks`、`civilization_checks` 通过；
- `s30`、`s32`、`s46` 进入固定机位预算；
- 每个重做的物件有四视图、灰度、剪影；主机位前后对比；
