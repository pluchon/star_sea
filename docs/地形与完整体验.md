本文保留此前原型的验证数据。「晨」的最新实现与验证见[类地星球完善记录](类地星球完善记录.md)。

## 可游玩内容

| 天体 | 地貌与体验 |
| --- | --- |
| 晨 | 半径 40 km。海岸、草原、连续山麓、山脊与高处积雪；风动草丛、散石和一处无人遗迹 |
| 烬 | 半径 26 km。沿固定风向排列的沙丘、宽阔台地和暗红岩坡；重力 5.8 m/s² |
| 霜 | 半径 32 km。冰蓝盆地、连续雪岭和裸露岩坡；重力 7.2 m/s² |
| 渊 | 带光环的背景气态巨星，不提供降落 |

三颗星球共享实际飞行、球面重力、距离分级地形和世界原点跟随。状态栏显示当前最近的星球，太阳、环境色和大气也随所在星球更新。

地形高度增加宽阔高地与山麓过渡，减少孤立尖峰；近地细节幅度降低，避免连续步行时细碎起伏。地表根据高度和坡度区分湿沙、沙滩、草地、岩石与积雪，使用连续颜色变化，不引入写实贴图。

海岸观景位置额外检查前方 350、800、1500 米处的水深，排除内陆浅洼；远峰还需通过沿途视线遮挡检查。泡沫沿浅水区域变化，远处波纹逐渐消失，避免高频细节产生条纹。深海保持不透明，浅水保留透明过渡；海面不写入深度，避免透明分块相互干扰。草石按切平面分块、固定种子分布，采样和实例位置计算在后台执行；主线程只创建和上传资源，离开区域后回收旧分块。

## 菜单、存档与声音

- 开始菜单和 Esc 暂停菜单；暂停时继续上传已经完成的地形，保证背景画面完整。
- 设置包含鼠标灵敏度、声音、渲染比例、视野、全屏和垂直同步。界面按窗口尺寸缩放，设置保存至 `user://settings.cfg`。
- 旅程保存相对星球的位置、观察方向、飞行或步行状态以及太阳方向，避免依赖浮动原点。保存先写临时文件，再替换 `user://journey.cfg`。读取时检查版本、星球、有限数值及方向有效性，失败时保留当前世界状态。
- 菜单退出和窗口关闭都会保存已经开始的旅程；保存失败会保留游戏并显示错误。
- 环境音包括风、近岸海浪与太空低音，步行时按实际移动距离触发脚步声。音频来自 `tools/Generate-Audio.py` 的确定性合成，没有第三方采样素材。自动检查确认播放状态，听感仍需人工试听。

角色在球面斜坡上可能产生微小上升速度，使默认地面吸附暂时失效。行走逻辑现在根据上一帧接地状态调用 `apply_floor_snap()`，并排除主动跳跃。接口依据：[Godot CharacterBody3D](https://docs.godotengine.org/en/4.7/classes/class_characterbody3d.html#class-characterbody3d-method-apply-floor-snap)。

## 验证与打包

验证输出保留在 `test-output/p2/`，不进入 Git。原技术小样记录见《第一阶段开发记录》，当前内容以本记录和新报告为准。

- 地形全局采样：20000 个方向，海面占比 39.68%，最高 2283.63 m，最低 -421.41 m。
- 几何验证：六个面共 6534 个顶点，球面位置、法线、三角形绕序及碰撞一致性通过。
- 三颗星球分别检查 480 个物理帧的行走，以及按各自重力计算时长的起跳、落地；贴地 479～480 帧，行走约 31.9 m，无明显地面穿透。
- 旅程往返分别覆盖三颗星球，检查覆盖保存、无效版本拒绝和位置恢复；设置另用专属测试文件往返，不覆盖用户设置或旅程。
- 真实渲染机位固定为 1920 × 1080、渲染比例 100%、关闭垂直同步。CPU 监控值仍是一秒峰值监控器，不视为逐帧 CPU 时间。
- 最终八个机位均通过：平均帧时间 4.33～7.21 ms，P95 最高 8.16 ms。逐机位数据与截图位于 `test-output/p2/release-shots/`。
- Windows Release 可执行文件的 60 秒降落：P99 7.732 ms，最大 9.281 ms，预热三秒后没有超过 50 ms 的帧，地形上传峰值 1.495 ms，最终距目标约 0.003 m。
- 三颗星球的行走检查与跳跃检查分别覆盖实际渲染和固定步长逻辑；最终逻辑报告为 `surface_checks.json`。打包版 40 秒行走位移 156.79 m，最低相对地面高度 -0.0048 m，报告为 `release-walk.json`。
- 打包版使用正常入口启动至菜单后退出，退出码为 0；菜单和设置另有 1080p、720p 截图。最终导出、降落、行走及正常启动日志没有引擎错误。

首次打包版降落曾在近景进入视野时出现一帧 263.269 ms 停顿，原始失败报告保留在 `regressions/descent-before-material-warmup.json`。现在启动时实例化隐藏草石，使引擎提前准备实例材质。按官方建议检查编译监控，并备份、重新生成 StarSea 的应用着色器缓存后再次验证；降落期间 Draw 编译数为 0、Surface 编译数为 1，没有超过预算的帧。本次没有清除显卡驱动的全局缓存。依据：[Godot 图形管线预编译](https://docs.godotengine.org/en/4.7/tutorials/performance/pipeline_compilations.html)。

`tools/Build-Game.ps1` 使用 Godot 4.7.2 官方 Windows x86_64 Release 模板生成嵌入资源的可执行文件，并附使用说明、Godot 许可证、第三方版权文件和 SHA256。交付目录为 `build/StarSea/`，压缩包为 `build/StarSea-Windows-x64.zip`。导出依据：[Godot Windows 导出文档](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_windows.html)。

本机模板从官方模板归档中按 HTTP 字节范围提取 Windows Release 两个条目；解压长度和 CRC32 与官方 ZIP 目录一致，没有下载完整归档进行整包 SHA256 校验。来源及各条目 SHA256 保存在 `test-output/p2/windows_template_provenance.json`。
