# 文档范围与完整验收记录

本文记录模型细化前的功能验收快照。后续自绘材质、模型细化和更新版本的结果见[卡通模型完善记录](卡通模型完善记录.md)。

本轮依据《方案》的三阶段内容完成交付，并按用户授权连续执行。美术基调沿用此前已初步认可的卡通表现；不增加战斗、任务、人物或写实材质。验收对象是三颗可降落星球与背景气态巨星组成的单人漫游体验。

## 本轮补充

- 飞行保护从终点高度检查改为沿位移检查首次地表接触，覆盖高速穿越山体或星球的情况。使用共享高度函数，在天体包围范围内每 8 米采样，并细分首次接触区间；不依赖尚未生成的物理地形。
- 设置与旅程先检查字段类型、有限数值和方向约束，再更新状态；异常文件不应导致部分设置生效。设置也采用临时文件替换，音量为零时关闭主音频总线。
- 环境音使用连续交叠循环，区分海岸、林地、高地与太空。脚步包含草地、沙地、岩石、雪地四种材质，每种三个变体；步距使用相对天体坐标，避免原点平移影响脚步。
- 新增统一验收命令，覆盖源代码检查、实际 Windows 打包版、截图、混音录音和压缩包校验。失败立即停止并保留日志，不生成通过结论。
- 暂停菜单隐藏游戏状态、帮助与性能面板，继续时恢复先前状态，避免设置面板与帮助文字重叠。

音频循环点按采样帧设置，依据 [AudioStreamWAV](https://docs.godotengine.org/en/stable/classes/class_audiostreamwav.html)。静音通过 [AudioServer](https://docs.godotengine.org/en/stable/classes/class_audioserver.html) 控制。验收录音使用主音频总线的 [AudioEffectRecord](https://docs.godotengine.org/en/stable/classes/class_audioeffectrecord.html)。

## 重复执行

```powershell
.\tools\Test-Acceptance.ps1
```

同一时间只能运行一个 Godot 或 StarSea 实例。检查不覆盖用户旅程和设置，使用独立的验证文件；快捷键检查会在用户截图目录保存一张截图。报告、日志、图片和录音保留在 `test-output/acceptance/`，不进入 Git。`summary.json` 的 `passed` 记录整套检查结果。

降落前会将 StarSea 自己的 `shader_cache` 和 `vulkan` 缓存移至本次报告目录下的 `cache-backups/`，用于检查应用冷缓存启动。副本保留，不修改显卡驱动的全局缓存。

验收脚本默认重新构建；`-SkipBuild` 仅用于检查当前已经生成的可执行文件。源代码改动后应重新构建。

## 人工确认范围

程序检查覆盖列明的有限场景，不能证明所有地点都没有错误。画面整体风格已获用户初步认可；最终声音听感、手动操作与持续探索体验由用户试玩确认。它们不计入自动检查的通过数量。

- 画面：查看海岸、林地与远山，按住 T 观察完整昼夜，确认配色、阴影和大气过渡。
- 操作：地面行走、加速和跳跃；按 F 起飞，环顾并返回地表，在离地两米内切回步行。
- 声音：比较海岸与林地的环境声，以及草地、沙地、岩石、雪地的脚步；设置音量为零后应完全静音。
- 旅程：保存后退出，再次启动并读取，确认位置、朝向、移动模式和太阳位置恢复。
