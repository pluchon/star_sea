# 方案：星海尽头

写于 2026-10-19。本文是整个项目的总体方案，各阶段的具体做法见对应的交接文档。

## 一、一句话

**一个人在星海中漂流，降落到荒凉而美丽的星球上，看远山、日落和满天星辰。** 采用塞尔达式的卡通画风，带有简单而好看的明暗，整体基调是寂寥感。

## 二、体验目标

| 体验 | 具体表现 |
| --- | --- |
| 星海遨游 | 在太空中自由飞行。背景是渐变的星云和密集的星点，天上悬着一颗带光环的巨大气态行星 |
| 降落 | 从太空飞向一颗星球，它从一个光点变成一颗带大气光晕的球，再变成脚下的大地。全程无缝，没有读条 |
| 地面 | 落地后步行。远处的山一层层地淡进天空色里，地平线微微弯曲 |
| 时间 | 太阳缓慢移动，同一个地方会经历白天、日落和夜晚。夜里抬头就是星海 |
| 寂寥 | 没有人，没有敌人，没有任务箭头。只有风、光、远山和星空 |

可以参考的作品：《塞尔达传说：旷野之息》的远景和明暗，《原神》的卡通着色，《光·遇》的天空，《星际拓荒》的星球尺度感，《Sable》的寂静。

## 三、画面风格

- **卡通明暗**：亮面和暗面分为两到三档，交界处略带柔和。暗面不是黑色，而是偏蓝紫的环境色。
- **边缘光**：物体轮廓带一圈淡淡的亮边。
- **固有色干净**：只用色块和渐变，不用写实纹理。
- **大气透视**：越远越淡，越接近天空色。远山的层次感主要来自这一点。
- **泛光**：太阳、日落和亮边带柔和的光晕。
- **不做**：物理正确的光照、全局光照、光线追踪、写实材质。

## 四、世界结构

第一阶段只做一颗可降落的星球，外加一颗作背景的气态行星。之后再扩展。

| 天体 | 规格 | 阶段 |
| --- | --- | --- |
| 星球"晨"（可降落） | 半径 40 公里，大气厚 8 公里，最高山约 2.5 公里，有海 | 第一阶段 |
| 气态巨星"渊"（背景） | 半径 90 公里，位于约 450 公里外，带光环，不可降落 | 第一阶段 |
| 更多可降落的星球 | 各有不同的地貌和配色 | 第二阶段 |

**为什么半径是 40 公里**：站在地面上，眼睛离地 1.7 米时，地平线约在 370 米外；1.5 公里高的山在约 11 公里外就能看见。这样脚下是一片大地，远处有层层的山。飞到几公里高时，就能看出星球是圆的。如果半径只有 5 公里，地平线只有 130 米，远山全被挡住，会像站在一个土包上。

## 五、技术方案

### 引擎：Godot 4.7.2（标准版，GDScript）

| 考虑的场景 | 结论 |
| --- | --- |
| 卡通明暗 | 可以直接写光照着色器，这是 Godot 的强项。虚幻的渲染管线为写实设计，做卡通只能绕路 |
| 星海、星云、天空 | 天空着色器加粒子 |
| 降落、大气 | 自己写一个风格化的大气壳着色器，同时负责从太空看到的光晕和地面上的远景淡化 |
| 远山 | 地形按距离分级细化，远处粗、近处细；大气壳负责远景淡化 |
| 太空尺度的坐标精度 | 用"世界原点跟着玩家走"的办法解决。虚幻内置双精度，这是它唯一占优的一项 |
| 780M 核显的性能 | 引擎开销小，这类画风本来就是为弱硬件设计的 |
| 开发效率 | 编辑器在核显上流畅，改动几秒钟就能生效；GDScript 简单，GPT 不容易写乱 |
| 打包 | 导出的 exe 约 100 MB |

虚幻 5 已从本机删除。Visual Studio 保留：如果星球地形生成在 GDScript 中太慢，就把这一部分改写成 C++ 扩展（godot-cpp）。其他部分一律使用 GDScript。

### 核心系统

| 系统 | 做法 |
| --- | --- |
| 世界原点跟随 | 宇宙中的所有天体挂在一个 `Universe` 节点下。玩家离原点超过 2 公里时，整个宇宙往回挪，玩家回到原点附近 |
| 星球地形 | 立方体投影到球面，6 个面各是一棵四叉树。离相机越近分得越细，最细一级每块约 40 米、32 × 32 格。地形块在后台线程中生成，主线程每帧最多上传几块 |
| 地形高度 | 多层噪声叠加：大陆、脊状山脉、丘陵和细节。同一个函数同时用于生成网格和查询高度 |
| 碰撞 | 只给玩家附近的最细一级地形块生成碰撞 |
| 海 | 地形块中低于海平面的部分，额外生成一层海面 |
| 大气 | 一个包住星球的球壳，着色器沿视线积分大气厚度。它同时负责三件事：从太空看到的光晕、地面上的天空颜色，以及远山的淡化 |
| 星空 | 天空着色器：渐变星云、程序化星点、太阳圆盘。白天由大气盖住，夜里或在太空中显现 |
| 卡通着色 | 公用的 `light()` 函数：两到三档明暗，暗面由环境色染成蓝紫 |
| 玩家 | 步行和飞行两种模式，按 F 切换。步行时重力指向星球中心；飞行时速度随高度变化，贴近地面慢，在太空中可达每秒几十公里 |
| 光照 | 只有一盏太阳光加环境色。太阳绕星球缓慢转动，形成昼夜 |
| 验证 | 用命令行参数驱动截图、测帧时间、自动降落和自动行走，输出 JSON |

### 性能预算（780M，1920 × 1080）

| 项目 | 要求 |
| --- | --- |
| 固定机位 | 平均 ≤ 12.5 ms，P95 ≤ 16 ms |
| 从太空降落到地面的全程 | P99 ≤ 20 ms，前 3 秒以后没有超过 50 ms 的帧 |
| 主线程 | 不在主线程生成地形 |

## 六、阶段

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| **第一阶段：技术小样** | 一颗可降落的星球、一颗气态巨星、星空、大气、海、卡通着色、步行与飞行、昼夜、验证工具 | 截图由用户确认风格；性能达到第五节的预算 |
| 第二阶段：星系 | 再加两颗风格不同的可降落星球；地表的小物件（石头、草、孤立的遗迹）；声音 | 用户试玩 |
| 第三阶段：完成度 | 菜单、设置、存档点、打包成 exe | 打包版在 780M 上流畅 |

用户于 2026-10-19 授权连续推进，不再逐阶段等待确认；保留各阶段的截图和验证记录，画面、听感与实际操控由用户试玩验收。之后进一步明确：文档作为参考，可根据实际效果调整，当前优先完善「晨」的地形、植被与光照。
