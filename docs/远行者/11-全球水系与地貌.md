# 规格 11：全球水系与地貌

## 一、目标

1. 把河流和湖泊从出发地附近 18 公里的样板区推广到整颗晨：每条河都从山上一路流进大海或湖里，不在任何边界上断掉。
2. 新增瀑布、峡谷、石林、温泉，让地貌更丰富。

## 二、为什么要离线烘焙

样板区的做法是启动时在 60 米格网上做一遍优先填洼。推广到全球时，不能"玩家走到哪里就算哪一块"：

- 河流会跨块，每块单独算，河在块的边界就断了；
- 高度函数必须是确定的（见 [工程约定](02-工程约定.md)）。地形块在区域算出来之前和之后得到不同的高度，就会出现裂缝和错位。

所以改成**离线烘焙**：用工具把整颗星球的水系预先算好，存成数据文件提交进仓库，游戏启动时直接读取。

## 三、烘焙

### 工具

| 文件 | 内容 |
| --- | --- |
| `game/scripts/tools/world_bake.gd` | `extends SceneTree`，无界面运行，算出全球水系和地貌数据，写入数据文件 |
| `tools/Bake-World.ps1` | Windows 上调用：`godot --headless --path game --script res://scripts/tools/world_bake.gd` |
| `game/scripts/planet/hydrology_data.gd` | `class_name HydrologyData extends Resource`，数据结构 |
| `game/data/dawn_world.res` | 烘焙结果，二进制资源，提交进仓库 |

烘焙在本机大约需要一两分钟，不需要每次运行游戏时做。**修改了基础地形（`TerrainNoise.base_height`）、火山参数或本规格里的任何阈值之后，必须重新烘焙。**

### 格网

用**球心投影的立方体格网**：六个面，每面 384 × 384 格，共约 88 万格。

- 格子中心方向：`(normal + axis_a * u + axis_b * v).normalized()`，`u`、`v` 是格子中心在 [-1, 1] 上的坐标，`normal`、`axis_a`、`axis_b` 沿用 `PlanetTerrain.FACES`。
- 方向反算格子：取绝对值最大的分量确定面，再用 `u = dir.dot(axis_a) / dir.dot(normal)`，`v = dir.dot(axis_b) / dir.dot(normal)`。
- 这里**不用**地形网格用的 `PlanetTerrain.cube_to_sphere`。那个映射没有简单的反函数，球心投影的反算简单而且精确。
- 格子大小：面中心约 208 米，角落约 70 米。
- 邻居：每格 8 个。面内直接加减下标；越过面的边界时，把 `normal + axis_a * u + axis_b * v` 中 `u` 或 `v` 超出 [-1, 1] 的三维点按上面的反算规则映射到相邻面。预先算好邻居表。

### 步骤

1. **基础高度**：每格 `base_height(方向)`，再叠加火山（见第五节）。
2. **优先填洼**：海面以下的格子全部作为种子，用第一阶段 `TerrainFeatures._flood` 同样的改进算法（堆加洼地先进先出队列）。球面是封闭的，没有区域边界种子。
3. **汇水面积**：按出队顺序倒序累加，每格面积按实际的球面面积计算（球心投影下格子大小不同，不能用常数）。
4. **湖泊**：填洼深度超过 4 米、面积不少于 0.12 平方公里、连通的格子为一个湖，水位取溢出口高度减 0.6 米。和样板区规则一致，只是阈值换成面积。
5. **河道**：上游汇水面积不少于 3 平方公里、流向大海或湖泊的格子为河道。从源头开始描线，汇水面积大的先描，支流在汇合处结束，进湖时截断、出湖口重新开始（与样板区相同）。
6. **平滑与蜿蜒**：
   1. 折线切角两次。
   2. 加蜿蜒：沿河道法向偏移 `A * sin(s / L + φ)`。其中 `s` 是沿河距离；振幅 `A = clamp(半宽 * 1.5, 3, 25)` 米；波长 `L` 在 80～200 米之间按河段随机；相位 `φ` 用河段编号派生。
   3. 重新以约 15 米的间距采样。
7. **水位**：每个点的水位不高于该点实际地面减 0.35 米，沿流向只降不升，最低为 -1（入海处）。
8. **河宽**：半宽 `clamp(3 + 2.2 * sqrt(汇水平方公里), 3.5, 28)` 米。
9. **瀑布与峡谷标记**：见第四节。
10. **空间索引**：每个面再分成 64 × 64 个桶，把每个河段放进它覆盖的所有桶（范围按半宽乘 3.5 加 60 米扩大）。桶的索引也一起烘焙。
11. **签名**：把 `terrain_noise.gd` 的源文件文本、火山参数和本步骤的所有阈值连起来，取 MD5，存进数据文件。

### 数据结构

```gdscript
class_name HydrologyData
extends Resource

@export var version: int = 1
@export var signature: String
# 河道：所有点首尾相接存放，river_starts[i] 是第 i 条河的第一个点
@export var river_points: PackedVector3Array      # 单位方向
@export var river_levels: PackedFloat32Array      # 水位，米
@export var river_widths: PackedFloat32Array      # 半宽，米
@export var river_flags: PackedByteArray          # 位 0 瀑布，位 1 峡谷
@export var river_starts: PackedInt32Array
# 湖：lake_cells 首尾相接存放格子编号
@export var lake_levels: PackedFloat32Array
@export var lake_cells: PackedInt32Array
@export var lake_starts: PackedInt32Array
# 空间索引：bucket_offsets[k] 到 bucket_offsets[k + 1] 是第 k 个桶里的河段编号
@export var bucket_offsets: PackedInt32Array
@export var bucket_segments: PackedInt32Array
# 地貌：火山、石林、温泉，见后文
@export var volcanoes: Array[Dictionary]
@export var karst_pillars: PackedVector4Array     # 方向 xyz（单位向量），w = 编号
@export var karst_sizes: PackedVector2Array       # 高度、半径
@export var hot_springs: PackedVector4Array       # 方向 xyz，w = 水池半径
```

### 运行时

- `TerrainFeatures` 改成从 `res://data/dawn_world.res` 读取，删除样板区的区域填洼（`_flood`、`_extract_lakes`、`_extract_rivers`）。
- `apply()`、`water_surface()`、`water_body()`、`river_distance()` 的接口不变，内部改为查全局空间索引。距离用三维弦长（方向乘半径），几公里内与弧长的误差可以忽略。
- 湖的格子查询用上面的反算规则得到格子编号，再查一张"格子编号 → 湖水位"的字典（加载时由 `lake_cells` 建好）。
- 火山、地标的位置也从数据文件读取，不再在运行时搜索。
- 出发地仍由 `SurfaceSites.find()` 用 `base_height` 选定，与烘焙无关。
- 加载失败或数据文件缺失时报错并停止，不要静默退回无河流的地形。

### `InlandWaters` 的改动

- 不能再一次性把全球的河面和湖面都建出来。改成按距离分块：以烘焙格网的桶为单位，玩家 3 公里内的桶建网格，离开 4 公里时释放。建网格放在后台线程，主线程只创建节点。
- 远处的大湖（面积超过 1 平方公里）另外建一个简化网格，在 20 公里内常驻，避免从高空看下去湖是空的。

## 四、瀑布与峡谷

### 瀑布

- 烘焙时检测：沿河连续的点中，水位下降与水平距离之比大于 0.35、且这一段累计落差超过 6 米，标为瀑布段。
- **地形**：瀑布顶保留一道岩坎；瀑布底挖一个水潭，半径为河道半宽的 1.6 倍，比水位再深 3 米。
- **水面**：瀑布段用 `inland_water.gdshader` 的"下落"变体：
  - 流纹速度乘 4，颜色更白，边缘水花更多；
  - 水潭处加一团水雾粒子（`GPUParticles3D`，约 40 个，白色半透明，向上缓慢扩散）。
- **声音**：在瀑布底放一个 3D 声源，循环播放新的 `waterfall.wav`，最大听距 220 米。
- 地形着色器在瀑布周围已经会因坡度露出岩石层理，不用另外处理。

### 峡谷

- 烘焙时检测：汇水面积超过 25 平方公里、地面海拔超过 250 米的河段，标为峡谷段。
- **地形**：峡谷段的河岸改为更宽更陡，`bank = 半宽 * 4 + 60`，坡度系数从 0.35 改为 0.9，两岸形成陡壁，地形着色器的层理色带会自然显现。
- 峡谷段两端各留 200 米逐渐过渡回普通河岸，避免突变。

## 五、新地貌

### 火山

- 晨上放两座：出发地附近那一座保留，规则与位置不变；另一座离出发地 12 公里以上，选在大陆内部高度 200～700 米的地方。
- 每座火山的参数存在 `volcanoes` 里：方向、山高、半径、火山口半径和深度、山脚基准高度。高度计算沿用 `TerrainFeatures.with_volcano`，改为遍历列表。

### 石林

- 在全星球放 3 片。条件：
  - `_geology` 噪声大于 0.6；
  - 海拔 250～900 米；
  - 湿度低于 0.45；
  - 坡度低于 0.25；
  - 离河道超过 150 米。
- 每片半径 400 米，放 25～40 根石柱：高 8～26 米、半径 2.5～6 米，柱距不小于 14 米，越靠片区中心越高越密。
- 石柱用 Blender 建模（建模方法按[规格 12](12-遗迹构件与模型规范.md) 第二节）：体素重建网格加噪声位移，竖向的风化沟槽，顶部草皮；做 6～8 个形状，缩放旋转后复用；碰撞用凸包。和第 5 步峡谷石柱、第 16 步海蚀柱共用同一套做法。
- 植被避开：每根石柱周围半径加 2 米不长草和树（`in_clearing` 一并处理）。

### 温泉

- 每座火山的山腰（离中心 0.55～0.75 倍半径）放 4 个温泉池，半径 6～10 米。池子沿等高线错开排列，从上往下逐级溢流。
- **地形**：池底比池边地面低 1.2 米。下坡方向做三级钙华台阶，每级高 0.8 米、宽 3 米。
- **颜色**：地形着色器新增最多 8 个温泉中心的数组参数，池边 25 米内的地面混入钙华白 `#EDE6D6` 和赭橙 `#D9873E` 的同心色带。
- **水面**：圆形水面网格，用 `inland_water.gdshader` 的"温泉"变体：浅处青绿 `#3FC1C0`，没有流纹，有缓慢的气泡亮点。加一团上升的白色蒸汽粒子。
- **声音**：新的 `spring.wav`（轻微的咕嘟声和水流声），3D 声源，最大听距 60 米。

## 六、对现有内容的影响

- 样板区的河湖会变成全球烘焙的结果，形状和数量会有变化。火山、海蚀柱、拱门、灯塔、石塔、巨环的位置不变，因为它们不依赖河流。
- 群系和地貌抽样数量、机位位置可能变化；`ShotCatalog` 里依赖地貌搜索的机位（`s16_terrace`、`s17_valley` 等）要确认仍然找得到。
- `TerrainMapData` 的全球地图（1024 × 512）会画出大湖；河太细，全球地图上看不出来，这是正常的。小地图能看到河。
- `terrain_statistics.gd` 里加入"河流""湖泊""瀑布""峡谷""石林""温泉"的抽样统计。

## 七、验收

### 自动检查

新建 `game/scripts/verify/hydrology_checks.gd`（可无界面）：

1. 数据文件存在，签名与当前源文件一致；不一致时 `passed = false`，提示需要重新烘焙。
2. 每条河的最后一个点在海里、湖里，或者是另一条河的点（汇合处）。
3. 每条河的水位沿流向不升高。
4. 随机抽 2000 个河道中心点：`height()` 都低于水位。
5. 出发地不在水里，离最近的河道中心超过 60 米。
6. 统计全球河流总长、湖泊数量和面积、瀑布数量、峡谷长度，写进报告。期望：
   - 河流总长 1500 公里以上；
   - 湖泊 100 个以上；
   - 瀑布至少 20 处，出发地 20 公里内至少 1 处。

   达不到时调整阈值并在记录里说明。
7. 在出发地周围 1 公里内随机调用 `height()` 10 万次：平均耗时不超过 6 微秒，写进报告。

### 人工确认

- 沿一条河从山上走到海边，河道连续，没有断头、悬空的水面和奇怪的台阶。
- 瀑布、石林、温泉、峡谷各有没有自己的特色，会不会让人想走过去看？
