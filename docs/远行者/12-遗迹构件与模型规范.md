# 规格 12：遗迹构件与模型规范

## 一、目标

建立一套远行者建筑的**标准构件库**。聚落、烽火塔、神殿、桥、水渠都用同一套构件拼出来，保证风格统一、尺寸咬合、性能可控。

外形、颜色、比例都以 [世界观与美术圣经](01-世界观与美术圣经.md) 第四、五节为准。

## 二、建模方式

> 2026-10-20 改写。原来的"路线 A：用 bpy/bmesh 在脚本里逐个写顶点和面""路线 B：用 GDScript 生成网格"作废：那样做出来的东西是几何体拼凑，雕像像积木、藤蔓像贴纸。用户的原则：**人和东西要用真正的建模工具做，不能是代码拼凑**；地形、洞穴、天梯这类超大尺度的东西继续程序生成。

### 原则

1. **用 Blender 的建模工具，而不是在脚本里写顶点。** GPT 只能通过 Python 操作 Blender，这没关系：脚本调用的应该是修改器、模拟、曲线、几何节点、雕刻用的位移这些建模工具，由它们产生形状。脚本里直接列出顶点坐标、拼面，只允许用于碰撞体和极简单的块（台阶、石板）。
2. **通用的自然物优先用 CC0 素材**（用户已同意）：石头、植物、藤蔓叶片这类东西，现成的高质量模型比自己生成的好得多。远行者独有的造型（雕像、人影、建筑构件、塔、天梯、飞船）自己建。
3. **仍然可以重复生成**：建模脚本在 `art/blender/`，CC0 原始文件放在 `art/sources/<来源名>/`，脚本读取、加工、导出。`tools/Build-Models.ps1` 一条命令重建全部模型。布料和刚体模拟用固定的帧数和种子，同一个 Blender 版本结果一致。
4. **画风统一**：素材只取几何形状，丢掉原有的贴图和材质，换成本项目的四种材质（见下文"材质"）。照片扫描的素材要减面到预算以内，不要保留照片级的细碎细节。
5. **先在 Blender 里自查再导出**：每个重做的构件，脚本用 EEVEE 渲一张四视图（正、侧、背、三分之二侧，中性灰底，一盏方向光），输出到 `test-output/models/<构件名>.png`。GPT 先看这张图，确认轮廓、比例、面的朝向没有问题，再进 Godot。这一步只花几秒，能挡住大部分低级问题。

### 常用做法

| 要做的 | Blender 里的做法 |
| --- | --- |
| 人体比例的基础形 | 在一串顶点（脊柱、四肢）上加"蒙皮"修改器（Skin），再加细分曲面，得到平滑的人体；或者直接用骨架加简单网格 |
| 姿势 | 给基础人体加骨架（Armature），用骨骼摆出站、跪、坐等姿势 |
| 长袍、兜帽、袖子 | 布料模拟（Cloth）：把长袍网格罩在摆好姿势的人体上，肩和颈固定，模拟若干帧让它自然垂坠，再应用。布料网格分辨率低一些，褶子就大而简洁，适合卡通风格 |
| 藤条、绳子、缆索 | 曲线（Curve）加倒角（Bevel），半径沿曲线渐细 |
| 叶子沿藤条分布 | 几何节点（Geometry Nodes）：在曲线上取点，实例化叶片模型，随机旋转和缩放 |
| 石头 | CC0 石头模型；或者二十面球 → 体素重建网格 → 噪声位移 → 减面 → 倒角 |
| 一堆碎石 | 刚体模拟（Rigid Body）：把石块从空中丢下，模拟到静止再应用，自然堆成中间高、边缘低、互相斜靠的一堆 |
| 断面 | 布尔差集，切割体先做噪声位移（现在的 `fracture()` 可以保留） |
| 墙、柱、台阶 | 倒角、阵列、实体化等修改器 |
| 减到面数预算 | 减面修改器（Decimate），最后一步做 |

### 面的朝向

所有面的法线必须朝外（朝向观看者能看到的一侧）。卡通光照会把朝里的面当成背光面，整片发黑，着色器里的背面翻转救不回来（第 4 步藤蔓发黑就是这个原因）。导出前在脚本里统一做一次"重新计算法线（朝外）"；开放的单面（叶片、布条）要按"离开附着面的方向"检查。

### 备用网格

`RuinKit` 现在会读 `geometry.json`（由导出脚本从同一批模型自动写出的三角形数据），在没有 glb 时使用。这不是第二套建模，可以保留，但**不再要求、也不允许为新构件在 GDScript 里手写网格**。

### 已有的东西

- 第 4 步做好的墙、门、石碑、柱子、台基等，用户已经认可，不重做。
- 飞船（`build_ship.py`）暂时不动，用户以后要求时再按新方法重做。
- 这一规则从第 4b 步开始，对之后所有新建模型生效（烽火塔、天梯的近景细节、洞口、晶石、钟乳石、提灯、软翼等）。

### 运行方式

- 运行方式：`blender --background --python art/blender/build_ruin_kit.py -- --out game/models/ruins`，在 `tools/Build-Models.ps1` 里封装。
- 要求 Blender 4.x。脚本开头检查版本，不满足就报错退出。
- 每个构件一个 glb 文件：`game/models/ruins/<构件名>.glb`。
- CC0 素材的来源、作者、链接、授权写进 `art/sources/来源.md`。只用明确标为 CC0 的素材。

### 坐标与单位

| 项目 | 规则 |
| --- | --- |
| 单位 | 1 = 1 米 |
| 上方 | Godot 里 +Y。Blender 里按 +Z 建模，导出时打开"+Y Up"（`export_yup=True`） |
| 正面 | Godot 里 -Z，就是门、台阶、雕像面朝的方向 |
| 原点 | 底面中心。墙段的原点在底边中点 |
| 模数 | 水平方向以 1 米为模数，墙厚 0.6 米，层高 3.6 米 |
| 变换 | 导出前应用所有变换（`export_apply=True`），物体缩放为 1 |

### 材质

每个构件最多用下面四种材质，**按名字区分**，导入时由代码换成项目的着色器材质。glb 里的材质颜色只用来在 Blender 里预览。

| 材质名 | 用途 |
| --- | --- |
| `stone` | 石材，绝大部分表面 |
| `patina` | 青绿铜锈的金属件 |
| `glyph` | 刻在石面上的琥珀色光纹，单独做成略微凹进的面片 |
| `cloth` | 布，旗和帘 |

- **UV**：石材按 1 米一格做立方体投影展开，让 `stone.svg` 的笔触大小在所有构件上一致。
- **顶点色**：R 通道是烘焙的环境光遮蔽（缝隙、底部暗一些，0.6～1）；G 通道是布料的摆动权重（只有 `cloth` 用，固定端 0，自由端 1）。

### 碰撞

- 在 Blender 里为每个构件建一个简化的碰撞体，物体名以 `-colonly`（凹体，用于桥面、台阶）或 `-convcolonly`（凸体，用于柱、石块）结尾。Godot 导入时会按名字自动生成碰撞，不渲染。
- 碰撞体的面数不超过 64。
- 台阶和坡道的碰撞做成斜面，不做一级一级的台阶，避免角色卡住。

### 细节层级

- 导入设置开启自动生成 LOD（`meshes/generate_lods = true`）。
- 面数上限（LOD0）：

  | 级别 | 例子 | 上限 |
  | --- | --- | --- |
  | 小件 | 石碑、灯柱、碎石 | 300 |
  | 中件 | 墙段、柱子、拱 | 1200 |
  | 大件 | 火盆、桥、穹顶 | 4000 |
  | 雕像 | 远行者雕像 | 5000 |

### 远行者雕像

- 修长的人形，身高约为人的 2.7 倍，比例比人更瘦更高；头部被兜帽遮住，看不到脸。
- 长袍垂到脚面，衣褶简单分成几大块，不做细碎的褶皱。
- 双手在胸前捧着一个小环（直径 0.6 米，`patina`）。
- 变体：站立、单膝跪地（高 2.8 米）、残破（缺头或缺一臂，断面不规则）。
- 巨像用同一个模型放大 3 倍（高约 14 米），用在神殿和天梯基座。

## 四、遗迹着色器

新建 `game/shaders/ruin.gdshader`，所有构件共用。

- 包含 `weather.gdshaderinc`（云影、晨雾、湿润）和 `toon_light.gdshaderinc`。
- `uniform int kind`：0 石材、1 铜锈、2 光纹、3 布。导入时按材质名给每个表面一份对应的材质。
- 实例参数：

  | 参数 | 范围 | 作用 |
  | --- | --- | --- |
  | `instance uniform float moss` | 0～1 | 苔藓量，由摆放处的湿度决定 |
  | `instance uniform float sand` | 0～1 | 积沙量，由摆放处的干燥程度决定 |
  | `instance uniform float awake` | 0～1 | 光纹亮度，被唤醒时从 0 渐变到 1 |
  | `instance uniform float base_height` | 米 | 构件底部离地面的高度，用来计算积沙的范围 |

- **石材**：
  - 底色 `#D6C7A4` 乘 `stone.svg` 的笔触；
  - 顶点色 R 压暗缝隙；
  - 朝上的面（世界法线与当地上方夹角小于 50°）按 `moss` 混入苔色；
  - 离地 0.8 米以内按 `sand` 混入沙土色；
  - 近处叠一层细裂纹（噪声取窄带），60 米外淡出。
- **铜锈**：青绿 `#5E8C84`，凹处更绿、凸处略透出暗铜色，边缘光略强。
- **光纹**：琥珀 `#F2B45A`，自发光强度 `mix(0.1, 2.0, awake)`，唤醒后有每 4 秒一次的缓慢呼吸。
- **布**：褪色赭红 `#B5654A`，按顶点色 G 随风摆动（使用 `wind_push`）。
- 湿润时整体压暗，与地形一致。

## 五、加载与摆放

### `RuinKit`

`game/scripts/civilization/ruin_kit.gd`：

```gdscript
class_name RuinKit
extends RefCounted

static func mesh(piece: String) -> Mesh                 # 优先读 glb，没有就用 geometry.json 里的备用数据
static func collision(piece: String) -> Array[Shape3D]  # 对应的碰撞形状
static func material(kind: int) -> ShaderMaterial       # 四种共享材质
```

- 加载结果缓存在静态字典里，同一个构件只读一次。
- glb 里的网格取第一个 `MeshInstance3D`，碰撞取名字以 `-colonly`、`-convcolonly` 结尾的节点生成的形状。
- 备用数据由 `ruin_meshes.gd` 读取 `geometry.json` 得到，不手写网格（见第二节"备用网格"）。

### `RuinBuilder`

`game/scripts/civilization/ruin_builder.gd`，负责把一组摆放数据变成节点：

```gdscript
class_name RuinBuilder
extends Node3D

# 每项：构件名、相对星球中心的变换、moss、sand、base_height、是否带碰撞
func build(placements: Array[Dictionary]) -> void
```

- 同一种构件按约 128 米的格子合并成一个 `MultiMeshInstance3D`，用 `INSTANCE_CUSTOM` 传实例参数（`MultiMesh` 不支持 `instance uniform`，所以 MultiMesh 路径下这四个参数改由 `INSTANCE_CUSTOM` 的四个通道传入，着色器两种路径都要支持）。
- 碰撞只在玩家 150 米内生成，离开 200 米时释放，与 `SurfaceDetails._refresh_colliders` 的做法相同。
- 可见距离：

  | 级别 | 可见距离 |
  | --- | --- |
  | 小件 | 250 米 |
  | 中件 | 1500 米 |
  | 大件和纪念物 | 不限 |

- 小件不投影，中件以上投影。

### 风化参数的来源

摆放时按位置自动计算，不要手工指定：

- `moss = smoothstep(0.45, 0.8, moisture) * (1 - smoothstep(900, 1400, 海拔))`；
- `sand = smoothstep(0.45, 0.25, moisture)`；
- 每个实例再加 ±0.1 的随机扰动。

## 六、验收

### 自动检查

新建 `game/scripts/verify/ruin_kit_checks.gd`（可无界面）：

1. 清单里的每个构件都能通过 `RuinKit.mesh()` 取到网格，面数不超过上限。
2. 每个构件的包围盒尺寸与清单相符（误差 5% 以内），原点在底面中心。
3. 每个需要碰撞的构件都有碰撞形状，面数不超过 64。
4. glb 和 `geometry.json` 备用数据的包围盒一致。
5. 开放的单面构件（藤蔓、布）朝外的法线占比达标（见规格 23 第六节）。

### 新机位

`s29_ruin_kit`：在出发地附近的一块平地上，把全部构件按 6 米间距排成几行（只在这个机位生成，正常游戏里不出现），从高处斜看，用来检查风格是否统一。

### 人工确认

- 构件放在一起，像同一个文明的东西吗？
- 和现有的海蚀柱、灯塔、石塔、巨环比，风格是否协调？如果不协调，以新构件为准，后续把这几处地标也改用构件重建。
